# Colors

fibo is achromatic. Greys do the structural work, and colour only ever carries
meaning. Components never name a colour: they read semantic tokens, and each
token points at one of Tailwind's primitives, per mode.

<RampMap />

## How the layers work

Three layers, and components only ever touch the last one.

1. **Primitives** are Tailwind's palette, as Tailwind ships it: `neutral-900`,
   `red-700`. fibo doesn't define its own.
2. **Semantic tokens** live in `globals.css`. Each names a job, such as
   `--primary` or `--destructive`, and points at a primitive once for light
   mode and once for dark.
3. **Utilities** come from `@theme inline`, which turns every semantic token
   into Tailwind classes: `bg-primary`, `text-muted-foreground`,
   `border-border`.

```css
/* globals.css */
:root {
  --primary: var(--color-neutral-900);
}

.dark {
  --primary: var(--color-neutral-50);
}

@theme inline {
  --color-primary: var(--primary);
}
```

```tsx
<button className="bg-primary text-primary-foreground">Save</button>
```

Swapping a theme means changing the second layer. Every component follows,
and none of them change.

## Named alpha roles

Tokens that end in `-subtle`, `-hover` or `-ring` are a colour at a set alpha,
such as `red-700 at 8%`. They exist instead of opacity modifiers like
`bg-destructive/10`, because Figma can't bind an opacity to a variable. Naming
the role keeps the alpha in one place and gives design and code the same name
to pick.

## Primitives

These are the only Tailwind steps fibo draws from: one grey ramp for
structure, and two steps of four hues, 700 in light mode and 400 in dark, for
status. The rest of [Tailwind's palette](https://tailwindcss.com/docs/colors)
is there if a theme needs it, but components never use primitives directly.
