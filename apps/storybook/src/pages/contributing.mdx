# Contributing

A new part needs a component file, a stories file, a docs page, a metadata
entry and a matching Figma component. The full checklist lives in the repo's
`add-component` skill (`.agents/skills/add-component/SKILL.md`), which people
and coding agents both follow. This page is the short version.

## Components or Niche

fibo has two shelves. **Components** are the standard parts most interfaces
need: they depend on nothing beyond Base UI, `class-variance-authority` and
`lucide-react`. **Niche** parts are built for one kind of moment, such as a diagram, a reading rail or a
reaction, and may use `motion`. Give a Niche part a `Niche/` title and it
lands in its own section of the sidebar and the catalog.

## Add a component

1. Create `packages/ui/src/components/<name>.tsx` in kebab-case.
2. Add `<name>.stories.tsx` next to it with an args-driven `Default` story and
   no `autodocs` tag.
3. Write its docs page at `apps/storybook/src/components/<name>.mdx`, using an
   existing page as the template.
4. Describe it in `packages/ui/components.meta.json`: title, description,
   tier and group. The registry, the catalog and `llms.txt` all read it.
5. Add a small preview for the catalog card in
   `apps/storybook/src/blocks/catalog.tsx`.
6. Run `pnpm format:write`, `pnpm lint`, `pnpm build` and `pnpm typecheck`.

## Docs page template

Component pages follow the same order so readers always know where to look:

1. Name and one-sentence description, then a playground: the live story and
   its controls in one frame.
2. **Import**: the install command and the import line.
3. **Usage** and **Accessibility** as numbered guidelines.
4. **Variants**, one canvas per story.
5. **Do's and don'ts**, as paired live examples.
6. **Related components**.
7. **Props**, a read-only reference generated from the component's types.

## Status tags

Add `new`, `beta` or `deprecated` to the `tags` array in a component's stories
meta and the sidebar renders it as a pill beside the name.
