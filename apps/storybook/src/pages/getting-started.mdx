# Getting started

fibo is a shadcn registry: add `@fibo/theme` to give shadcn's components fibo's
colors in light and dark, or install parts shadcn doesn't have, such as Command
menu, Filter menu and Reactions.

## What the registry is

One JSON file per component at `fibo.toribryan.com/r`, holding its code and
what it needs. The shadcn CLI reads these files and copies components into your
project as source. Every component, property and color variable has the same
name in fibo's Figma library and in code.

An installed part is a copy, not a link. You can edit anything in it, and a fibo
update never changes it until you add the part again.

## Before you start

You need a shadcn project, with a `components.json` at its root. To set one up:

```bash
pnpm dlx shadcn@latest init
```

`npx` works in place of `pnpm dlx` in every command. To use a coding agent
instead, see [With a coding agent](#with-a-coding-agent).

## 1. Connect fibo to your project

Add to `components.json`:

```json
"registries": {
  "@fibo": "https://fibo.toribryan.com/r/{name}.json"
}
```

Keep `{name}` literal; the CLI replaces it with the requested part's name.
Projects started from `toribryan/design-project-template` already have this
entry.

## 2. Add a component

```bash
pnpm dlx shadcn@latest add @fibo/button
```

`add` does four things:

1. **Writes the code** to `components/ui/button.tsx`.
2. **Installs packages** the component is built on, such as Base UI, which
   handles keyboard, focus and screen readers.
3. **Adds the fibo parts it uses.** Toast brings Button, for its action and
   close controls.
4. **Adds tokens.** Any color token the part uses that your project lacks goes
   into `globals.css`, in light and dark. Existing tokens are left alone.

The inspector reads the same files as the CLI.

<RegistryInspector />

Several parts at once:

```bash
pnpm dlx shadcn@latest add @fibo/button @fibo/input @fibo/select
```

Without step 1, the full URL works in any shadcn project:

```bash
pnpm dlx shadcn@latest add https://fibo.toribryan.com/r/button.json
```

The <DocLink to="catalog--docs" className="text-foreground underline underline-offset-4">Catalog</DocLink> lists every part.

## 3. Use it on a page

```tsx
import { Button } from "@/components/ui/button"

export function Toolbar() {
  return (
    <Button variant="outline" size="sm">
      Save draft
    </Button>
  )
}
```

Props match Figma component properties: `variant="outline"` is the `variant`
property set to outline, and `size` and `checked` work the same way. Each
component page has a playground and a table of every option.

## 4. Make it look like fibo

After step 2, parts use your project's colors for standard roles such as
primary, background and borders, and fibo's only for the extras, so fibo fits
an existing product without restyling it.

To use fibo's colors everywhere:

```bash
pnpm dlx shadcn@latest add @fibo/theme
```

This replaces the color values in `globals.css` with fibo's, in light and dark.
Each color is a role, such as `primary` or `border`, that points at a value in a
color ramp. To retheme, edit `:root` and `.dark` in `globals.css`.

## 5. Change it

An installed file such as `components/ui/button.tsx` is yours: add a variant,
change a radius, delete what you don't use. fibo never overwrites it.

Style with tokens like `bg-primary`, never raw colors like `bg-neutral-900` or
`#171717`. Tokens follow dark mode and the theme; raw colors don't. <DocLink to="foundations-colors--docs" className="text-foreground underline underline-offset-4">Colors</DocLink> lists every token and its use.

## 6. Get updates

Installed code doesn't update automatically. To take the latest version of a
part:

```bash
pnpm dlx shadcn@latest add @fibo/button --overwrite
```

This replaces the whole file, including your edits. The <DocLink to="changelog--docs" className="text-foreground underline underline-offset-4">Changelog</DocLink> lists what changed.

<Tip tone="warning" title="Edited a part?">
  `--overwrite` discards your edits. Commit first so you can compare and undo.
  For a heavily changed part, treat it as your own component and copy in only
  the fibo changes you want.
</Tip>

## How it works

<RegistryFlow />

1. **Designed in Figma.** Each component and its properties start in the Figma
   library, built with fibo's color variables.
2. **Built in code.** The component is written in fibo's repo with the same
   names. Its colors come from tokens in `globals.css`, which match the Figma
   variables one to one.
3. **Built into registry files.** A build step reads each component, records
   the packages and fibo parts it uses and the tokens its classes use, and
   writes one file per part, plus `llms.txt`.
4. **Published.** The files go live at `fibo.toribryan.com/r` with this site on
   every merge.
5. **Checked.** Before a change merges, CI installs every part into a new
   project and builds it. A part that would arrive missing a token, such as a
   hover color, blocks the change.
6. **Installed.** `add` downloads the part's file and writes its code, packages
   and tokens into your project.

Button's registry file, trimmed:

```json
{
  "name": "button",
  "dependencies": ["@base-ui/react", "class-variance-authority"],
  "registryDependencies": ["utils"],
  "files": [
    {
      "path": "registry/ui/button.tsx",
      "content": "import { Button as ButtonPrimitive } from ..."
    }
  ],
  "cssVars": {
    "light": {
      "primary-hover": "color-mix(in oklch, var(--color-neutral-900) 80%, transparent)"
    },
    "dark": {
      "primary-hover": "color-mix(in oklch, var(--color-neutral-50) 80%, transparent)"
    }
  }
}
```

- `dependencies`: packages to install.
- `registryDependencies`: registry parts to add first. `utils` is shadcn's
  class-name helper.
- `files`: the component's full code, which becomes your file.
- `cssVars`: tokens to add, for light and dark.

**Raw file** in the inspector opens any part's real file.

## Run fibo locally

Clone the repo, then:

```bash
pnpm install
pnpm storybook
```

Storybook runs at `localhost:6006`. `AGENTS.md` documents the repo layout and
the registry build.

## Troubleshooting

### "Unknown registry @fibo"

Step 1 is missing, or `components.json` has a typo or invalid JSON. Check that
`"@fibo"` is inside `"registries"`.

### A part has no hover color or focus ring

It was probably added before 30 September 2026, when parts started bringing
their own tokens. Add it again with `--overwrite`, or add `@fibo/theme`.

### It asks whether to overwrite a file

A file with that name exists, often shadcn's own version of the same part, such
as `components/ui/button.tsx`. Yes replaces it, including your edits. See
[step 6](#6-get-updates).

### My project already has shadcn's own components

fibo parts sit beside them. Only a part with the same name replaces one.

### Does it work without Tailwind?

No. fibo parts are styled with Tailwind CSS 4, which `shadcn init` sets up.
