# Getting started

There are two ways to use fibo in a project built on shadcn:

- **Use the fibo theme.** Keep shadcn's components and add `@fibo/theme` to
  give them fibo's colors, in light and dark.
- **Add special components.** Install fibo's own parts, such as Command menu,
  Filter menu and Reactions, which shadcn doesn't have.

This guide shows how to do either.

## What the registry is

If you've used a Figma team library, you already know most of it. fibo's Figma
library and its code are one system: every component, property and color
variable has the same name in both.

The registry is how the code half is shared. It's a set of files at
`fibo.toribryan.com/r`, one per component. Each file holds the component's code
and a list of what it needs to work. A free tool called the **shadcn CLI**
reads those files and copies components into your project.

The difference from a Figma library is what happens after you add something:

<LibraryComparison />

Copying instead of linking is on purpose. You can change anything about a part
without waiting on anyone, and a fibo update never changes your product by
surprise.

## Before you start

You need a project that already uses shadcn, the most common way React
projects set up their components. Such a project has a `components.json` file
in its top folder. If yours doesn't, this command sets it up:

```bash
pnpm dlx shadcn@latest init
```

It asks a few questions; the defaults are fine.

Run every command on this page in a terminal, inside your project's folder.

<Tip title="First time in a terminal?">
  The commands need Node.js, a free install from
  [nodejs.org](https://nodejs.org) that includes `npx`. This page uses `pnpm`,
  which does the same job. If you don't have pnpm, replace `pnpm dlx` with `npx`
  in every command.
</Tip>

Working in Claude Code, Cursor or another coding agent? Paste the prompts
under [With a coding agent](#with-a-coding-agent) instead of typing
commands.

## 1. Connect fibo to your project

This is like turning on a library in Figma's Assets panel: it tells your
project where fibo lives. Open `components.json` and add this inside its outer
braces, next to the settings already there:

```json
"registries": {
  "@fibo": "https://fibo.toribryan.com/r/{name}.json"
}
```

Put a comma after the setting just above it, or the file won't read. Leave
`{name}` exactly as written. The CLI replaces it with the name of the part
you ask for. Projects started from `toribryan/design-project-template` already
have this line.

## 2. Add a component

```bash
pnpm dlx shadcn@latest add @fibo/button
```

The command does four things:

1. **The code arrives.** The CLI writes the component to
   `components/ui/button.tsx`.
2. **Packages install.** The CLI installs the packages the component is built
   on, such as Base UI, which handles keyboard, focus and screen readers.
3. **Other fibo parts come too.** A part built from another part brings it:
   Toast brings Button, because its action and close controls are buttons.
4. **Tokens are added.** The CLI adds any color token the part uses that your
   project lacks to `globals.css`, in light and dark. It leaves tokens you
   already have alone.

The inspector below reads the same files as the CLI. Pick a component to see
what it brings.

<RegistryInspector />

To add several parts at once:

```bash
pnpm dlx shadcn@latest add @fibo/button @fibo/input @fibo/select
```

Without step 1, the full URL works in any shadcn project:

```bash
pnpm dlx shadcn@latest add https://fibo.toribryan.com/r/button.json
```

The <DocLink to="catalog--docs" className="text-foreground underline underline-offset-4">Catalog</DocLink> shows every part you can add.

## 3. Use it on a page

```tsx
import { Button } from "@/components/ui/button"

export function Toolbar() {
  return (
    <Button variant="outline" size="sm">
      Save draft
    </Button>
  )
}
```

**The props are the Figma properties.** `variant="outline"` in code is the
`variant` property set to outline in Figma, and `size` and `checked` work the
same way. What you set in a mockup is what a developer types.

Every component page in this Storybook has a playground to try the props and a
table of every option.

## 4. Make it look like fibo

After step 2, your parts use your project's colors for everything standard,
such as primary, background and borders, and fibo's only for the few extras.
That's on purpose, so fibo fits into an existing product without restyling
it.

To make everything look as it does here, add the theme:

```bash
pnpm dlx shadcn@latest add @fibo/theme
```

This replaces the color values in your `globals.css` with fibo's, in light
and dark.

Every color is a role, such as `primary` or `border`, that points at a value
in a color ramp. To retheme, edit `:root` and `.dark` in `globals.css`;
nothing else needs to change.

## 5. Change it

The component file is yours now. Open `components/ui/button.tsx` and edit it:
add a variant, change a radius, or delete what you don't use. Nothing in fibo
overwrites it.

One rule keeps it on-system: style with **tokens** like `bg-primary`, never raw
colors like `bg-neutral-900` or `#171717`. Tokens follow dark mode and your
theme; raw colors stay the same everywhere. The <DocLink to="foundations-colors--docs" className="text-foreground underline underline-offset-4">Colors</DocLink> page lists every token and what it's for.

## 6. Get updates

Because the code is a copy, fibo updates don't reach you automatically. To take
the latest version of a part:

```bash
pnpm dlx shadcn@latest add @fibo/button --overwrite
```

This replaces the whole file, including any edits you made. The <DocLink to="changelog--docs" className="text-foreground underline underline-offset-4">Changelog</DocLink> says what changed.

<Tip tone="warning" title="Edited a part?">
  Updating works like resetting all overrides: your edits are lost. Once you've
  changed a part a lot, treat it as your own component and copy in only the fibo
  changes you want. Before you update, make a git commit so you can compare and
  undo.
</Tip>

## How it works

A part's path from the Figma library to your project:

<RegistryFlow />

1. **Designed in Figma.** Each component and its properties start in the
   Figma library, built with fibo's color variables.
2. **Built in code.** The component is written in fibo's repo with the same
   names. Its colors come from tokens in one file, `globals.css`, which
   matches the Figma variables one to one.
3. **Turned into registry files.** A build step reads each component, notes
   the packages and other fibo parts it uses, looks up the tokens its classes
   use, and writes one file per part. It also writes `llms.txt`.
4. **Published.** The files go live at `fibo.toribryan.com/r` with this site
   each time a change is merged.
5. **Checked.** Before any change is merged, an automated test installs every
   part into a new project and builds it. If a part would arrive missing a
   token, such as a hover color, the change can't ship.
6. **Installed.** When you run `add`, the CLI downloads the part's file and
   writes its code, packages and tokens into your project.

A registry file is plain JSON. Here's the shape of Button's, trimmed:

```json
{
  "name": "button",
  "dependencies": ["@base-ui/react", "class-variance-authority"],
  "registryDependencies": ["utils"],
  "files": [
    {
      "path": "registry/ui/button.tsx",
      "content": "import { Button as ButtonPrimitive } from ..."
    }
  ],
  "cssVars": {
    "light": {
      "primary-hover": "color-mix(in oklch, var(--color-neutral-900) 80%, transparent)"
    },
    "dark": {
      "primary-hover": "color-mix(in oklch, var(--color-neutral-50) 80%, transparent)"
    }
  }
}
```

- `dependencies` are the packages to install.
- `registryDependencies` are other registry parts to add first. `utils` is
  shadcn's small helper for combining class names.
- `files` holds the component's full code, which becomes your file.
- `cssVars` holds the tokens to add, once for light mode and once for dark.

Use **Raw file** in the picker above to open any part's real file.

## Run fibo locally

To work on fibo itself, clone the repo and run:

```bash
pnpm install
pnpm storybook
```

Storybook runs at `localhost:6006`. `AGENTS.md` documents the repo layout and
the registry build.

## Troubleshooting

### "Unknown registry @fibo"

Step 1 is missing, or `components.json` has a typo. Check that `"@fibo"` sits
inside `"registries"` and that the file is still valid JSON: every entry
except the last ends with a comma.

### A part has no hover color or focus ring

It was probably added before 30 September 2026, when parts started bringing
their own tokens. Add it again with `--overwrite`, or add `@fibo/theme`.

### It asks whether to overwrite a file

You already have a file with that name, often shadcn's own version of the same
part, such as `components/ui/button.tsx`. Saying yes replaces it, and any edits you
made, with fibo's. See [step 6](#6-get-updates) first.

### My project already has shadcn's own components

That's fine. fibo parts sit beside them, and only a part with the same name
replaces one.

### Does it work without Tailwind?

No. fibo parts are styled with Tailwind CSS 4, which `shadcn init` sets up for
you.

## Words on this page

- **Registry**: a set of files, one per component, that a tool can install
  from. fibo's lives at `fibo.toribryan.com/r`.
- **shadcn CLI**: the command-line tool that reads registries and copies
  components into a project. `pnpm dlx shadcn@latest` runs it without
  installing anything.
- **Terminal**: the app where you type commands. VS Code, Cursor and most
  code editors have one built in.
- **`components.json`**: your project's shadcn settings, including which
  registries it can install from.
- **`globals.css`**: the stylesheet that holds your project's tokens, in light
  and dark.
- **Token**: a named color, such as `--primary`, that points at a real
  value per mode. The code version of a Figma color variable.
- **Package**: code someone else maintains that a component is built on,
  installed for you by the CLI.
- **Part**: one fibo component, such as Button or Select.
- **Prop**: a setting on a component in code. The code version of a Figma
  component property.
- **Git** and **commit**: git keeps your project's history. A commit is a
  saved version you can compare against or go back to.
- **Merged**: reviewed and added to fibo's main code. Merging a change
  publishes it.
