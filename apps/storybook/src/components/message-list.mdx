# Message list

A message list shows a conversation, grouping each person's messages in a row
under one heading with their name and picture. A group ends when the author
changes, the day changes, or enough time passes.

<Canvas of={Stories.Default} />

## Features

- Every reason a group breaks is a named rule you can test, and each message
  reports which one started its group.
- The time window is a setting, measured from the previous message (rolling)
  or from the group's first (fixed).
- Each group's author is a real heading, and every message names its author
  and time for screen readers, even mid-group.
- One tab stop for the whole list. Arrow keys move between messages, Enter
  goes into one, Escape comes back out.

## Examples

### Rolling or fixed window

Five messages, four minutes apart. Measured from the previous message, the
window never runs out and they stay one group. Measured from the first, a new
group starts once five minutes have passed since it began.

<Canvas of={Stories.Window} />

### Unread

`unreadFrom` names the first unread message. The divider above it is red with
a "New" label, so it doesn't rely on color alone, and it breaks the group.
Freeze the value when the conversation opens, so the line stays where it was
while people read; clear it when they send a message, press Escape or mark
the conversation read. Pair it with the
[Jump bar](?path=/docs/base-components-actions-jump-bar--docs).

<Canvas of={Stories.Unread} />

### With a divider

`dividers` maps a message id to a label. The divider sits above that message,
and the message starts a new group.

<Canvas of={Stories.Divider} />

### Custom spacing

Space between groups and space within a group are two separate values,
`--message-group-gap` and `--message-gap`. Change the first for a more open
list without pulling a group's messages apart.

<Canvas of={Stories.Spacing} />

### Translated

Times and dates follow `locale`. `strings` holds the list's name, the screen
reader labels and the deleted message text.

<Canvas of={Stories.Translated} />

### Empty

With no messages, the list shows `strings.empty` in an EmptyState. Pass
`empty` to show your own, or `null` to show nothing.

<Canvas of={Stories.Empty} />

## Usage

```ts
type ChatMessage = {
  id: string
  author: { id: string; name: string; avatar?: string }
  sentAt: Date
  content: React.ReactNode
  kind?: "message" | "system"
  deleted?: boolean
  replyTo?: { id: string; name: string; text: string }
}
```

```tsx
import { MessageList, type ChatMessage } from "@/components/ui/message-list"

export function Channel({ messages }: { messages: ChatMessage[] }) {
  return (
    <div className="h-96 overflow-y-auto">
      <MessageList messages={messages} aria-label="#design" />
    </div>
  )
}
```

Pass the whole conversation, oldest first. Grouping looks at each message's
neighbors, so a list that only holds the rows on screen would start a new
group at the top of every scroll. If you virtualize, call `groupMessages` on
the full list and render from its result.

### Break rules

`groupMessages` checks these in order, and the first that holds is the
message's `breakReason`. The first message in the list is `start`.

| Rule       | A new group starts when                                      |
| ---------- | ------------------------------------------------------------ |
| `divider`  | the message has a divider above it                           |
| `day`      | the message is on a different day from the one before        |
| `system`   | this message or the one before is a system message           |
| `deleted`  | this message or the one before was deleted                   |
| `reply`    | the message is a reply                                       |
| `author`   | a different person sent it                                   |
| `identity` | the same person sent it under a new name or picture          |
| `window`   | more than `windowMinutes` have passed since the window began |

Each message also gets a `position` of `single`, `first`, `middle` or
`last`, rendered as `data-position`. Bubble layouts use it to square off the
corners where bubbles meet.
