# Chat composer

The box people write messages in. It is a set of parts around one draft, not
one component with a prop for every case: each chat surface picks the parts it
needs, puts them in its own order, and adds its own elements beside them.

<Canvas of={Stories.Default} />

## Features

- A provider holds the draft and how to change and send it. The frame, header,
  text box, footer, actions and send button read it from context, so they work
  in any order and anywhere below it, even outside the frame.
- The parts never own state. `LocalComposerProvider` keeps the draft in
  component state; pass your own state and actions to `ComposerProvider` to
  keep it in a store, on a server, or synced across devices.
- Enter sends, Shift+Enter breaks the line, and the text box grows with the
  draft. Attachments come from a file picker or a drop.
- No boolean props for features. Drag and drop, mentions and attachments are
  parts: render one to turn it on, leave it out to turn it off.

## Usage

```tsx
import {
  ComposerCommonActions,
  ComposerFooter,
  ComposerFrame,
  ComposerInput,
  ComposerSubmit,
  LocalComposerProvider,
} from "@/components/ui/chat-composer"

export function ChannelComposer() {
  return (
    <LocalComposerProvider onSubmit={({ value }) => sendMessage(value)}>
      <ComposerFrame>
        <ComposerInput placeholder="Message #design" />
        <ComposerFooter>
          <ComposerCommonActions />
          <ComposerSubmit />
        </ComposerFooter>
      </ComposerFrame>
    </LocalComposerProvider>
  )
}
```

When a surface needs something the parts don't do, write it as JSX beside
them rather than adding a prop to a part.

### Bring your own state

Every part talks to this interface and nothing else. Render
`ComposerProvider` with your own `state` and `actions` and the same parts run
on them:

```ts
type ComposerState = {
  value: string
  attachments: ComposerAttachment[]
  submitting?: boolean
  disabled?: boolean
  canSubmit?: boolean // defaults to having text or an attachment
}

type ComposerActions = {
  setValue: (value: string) => void
  addAttachments: (files: File[]) => void
  removeAttachment: (id: string) => void
  submit: () => void
}

type ComposerAttachment = {
  id: string
  name: string
  size?: number // bytes
  file?: File
}
```

```tsx
function SyncedComposerProvider({ children }) {
  const state = useSyncExternalStore(draft.subscribe, draft.get)
  const actions = useMemo(() => createDraftActions(draft), [])
  return (
    <ComposerProvider state={state} actions={actions}>
      {children}
    </ComposerProvider>
  )
}
```

Custom parts read the same context with `useComposer()`, which returns
`{ state, actions, meta }`, with the text box at `meta.inputRef`.

## Guidelines

<UsageGuidelines
  guidelines={[
    "Compose a variant from parts instead of adding a prop. An edit box, a thread reply and a forward dialog are three compositions of the same parts.",
    <>
      Keep state out of the parts. If the draft has to survive a reload or
      follow someone across devices, swap <code>LocalComposerProvider</code> for
      a <code>ComposerProvider</code> fed by your store.
    </>,
    <>
      Put the provider around everything that needs the draft. A send button in
      a dialog's footer, outside the frame, still works when it's inside the
      provider.
    </>,
    <>
      Leave <code>ComposerCommonActions</code> out when a composer needs a
      different set, and list the actions it does need.
    </>,
    <>
      Return a promise from <code>onSubmit</code> when sending takes a round
      trip. The send button shows it's busy, and a rejection keeps the draft.
    </>,
  ]}
/>

remove button.

### Minimal

A text box and a send button in one row, with no header, footer or drop zone.

### Disabled

`disabled` on the provider turns off the text box and every action.

<Canvas of={Stories.Disabled} />

### Edit message

Editing a sent message: a header says so, the footer swaps the actions for
Cancel and Save, and Escape cancels through the text box's own `onKeyDown`.
No `isEditing` prop.

<Canvas of={Stories.EditMessage} />

### Thread reply

A reply in a thread, with a checkbox to also post it to the channel. The
checkbox is ordinary JSX in the footer, and the story's `onSubmit` reads it.

<Canvas of={Stories.ThreadReply} />

### Submit outside the frame

A forward dialog whose Forward button sits in the dialog's footer, outside
the frame. It sends because it's inside the provider. The note is optional,
so the provider's `canSubmit` lets an empty draft through.

<Canvas of={Stories.SubmitOutsideTheFrame} />

### Synced draft

Two composers on one store, as a draft synced between a laptop and a phone
