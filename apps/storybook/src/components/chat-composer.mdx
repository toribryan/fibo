# Chat composer

A message input built from composable parts around one shared draft, with
attachments, native emoji, suggested replies and slash commands. Type / in the
example to open its commands.

<Canvas of={Stories.Default} />

<DocTabs>

<DocTab value="build" label="Build">

## Features

- A provider holds the draft and its actions. Every part reads it from
  context, so parts work in any order and anywhere below it, even outside the
  frame.
- Parts own no state. `LocalChatComposerProvider` keeps the draft in component
  state; `ChatComposerProvider` takes external state and actions from a store,
  a server or a sync layer.
- Enter sends, Shift+Enter breaks the line, and the text box grows with the
  draft. Attachments come from a file picker or a drop anywhere on the
  conversation, and show their upload status.
- Typing / at the start of a word opens fibo's Command menu. The emoji button
  opens a grid of native emoji, the mic dictates into the draft, and
  suggested replies fill the draft in one tap.
- No boolean feature props. Drag and drop, emoji, commands, dictation and
  suggested replies are parts: render one to enable it, omit it to disable it.

## Examples

### With attachments

Picked or dropped files show in the header as Attachment parts:
images as thumbnails, other files as chips. Each shows its upload, and send
waits until every one is ready.

<Canvas of={Stories.WithAttachments} />

### Suggested replies

Each suggestion fills the draft and hands focus back. It never sends, so
people can change it first.

<Canvas of={Stories.SuggestedReplies} />

### Emoji

Native emoji in a grid, inserted at the caret. Browsers can't open the
system's own picker, so the composer brings a small one; `emojis` sets the
list.

<Canvas of={Stories.Emoji} />

### Dictation

The mic turns speech into text at the caret, with words landing in the draft
as they are heard; press it again or Escape to stop. It uses the browser's
speech recognition and hides itself where there is none, such as Firefox.
This example plays a scripted voice; `recognition` takes any engine with the
same shape.

<Canvas of={Stories.Dictation} />

When dictation stops on an error, such as a blocked microphone or a long
silence, the mic's tooltip opens with the reason for a few seconds.
`errorMessages` rewords them.

<Canvas of={Stories.DictationBlocked} />

### On a touch screen

Where a coarse pointer is the main input, the composer changes on its own:
Common actions collapse into a + that opens a bottom sheet of labeled rows,
emoji and dictation step aside for the phone keyboard's own, controls grow to
40px, Return adds a line, suggestions scroll in one row, and the text box
stops at a third of the screen. `pointer="coarse"` forces it, as here.

<Canvas of={Stories.Touch} />

### Minimal

A text box and send button in one row. No header, footer or drop zone, so it
can go down to 160px with `min-w-40`.

### Disabled

`disabled` on the provider turns off the text box and every action.

### Edit message

## Usage

```tsx
import {
  ChatComposerCommonActions,
  ChatComposerFooter,
  ChatComposerFrame,
  ChatComposerInput,
  ChatComposerSubmit,
  LocalChatComposerProvider,
} from "@/components/ui/chat-composer"

export function ChannelComposer() {
  return (
    <LocalChatComposerProvider onSubmit={({ value }) => sendMessage(value)}>
      <ChatComposerFrame>
        <ChatComposerInput placeholder="Message #design" />
        <ChatComposerFooter>
          <ChatComposerCommonActions />
          <ChatComposerSubmit />
        </ChatComposerFooter>
      </ChatComposerFrame>
    </LocalChatComposerProvider>
  )
}
```

Add surface-specific behavior as JSX beside the parts, not as a prop on a
part.

### Bring your own state

Parts depend only on this interface. Pass `state` and `actions` to
`ChatComposerProvider` to run them on external state:

```ts
type ChatComposerState = {
  value: string
  attachments: ChatComposerAttachment[]
  submitting?: boolean
  disabled?: boolean
  canSubmit?: boolean // defaults to having text or an attachment
}

type ChatComposerActions = {
  setValue: (value: string) => void
  addAttachments: (files: File[]) => void
  removeAttachment: (id: string) => void
  retryAttachment?: (id: string) => void
  submit: () => void
}

type ChatComposerAttachment = {
  id: string
  name: string
  size?: number // bytes
  file?: File
  status?: "ready" | "loading" | "error" // send waits until all are ready
  error?: string
}
```

```tsx
function SyncedComposerProvider({ children }) {
  const state = useSyncExternalStore(draft.subscribe, draft.get)
  const actions = useMemo(() => createDraftActions(draft), [])
  return (
    <ChatComposerProvider state={state} actions={actions}>
      {children}
    </ChatComposerProvider>
  )
}
```

Custom parts read the context with `useChatComposer()`, which returns
`{ state, actions, meta }`, with the text box at `meta.inputRef`. Slash
commands use it the same way:

```tsx
function SlashCommands() {
  const { state, actions } = useChatComposer()
  return (
    <ChatComposerCommandMenu
      groups={[
        {
          label: "Commands",
          items: [
            {
              value: "shrug",
              label: "Shrug",
              onSelect: () => actions.setValue(`${state.value} ¯\\_(ツ)_/¯`),
            },
          ],
        },
      ]}
    />
  )
}
```

With `LocalChatComposerProvider`, pass `upload` to run each attachment's
upload: it shows loading while the promise runs and offers retry if it
rejects.

## Guidelines

<UsageGuidelines
  guidelines={[
    "Compose variants from parts instead of adding props. Edit, thread reply and forward are compositions of the same parts.",
    <>
      Keep state out of the parts. For a draft that survives reloads or syncs
      across devices, replace <code>LocalChatComposerProvider</code> with a{" "}
      <code>ChatComposerProvider</code> fed by your store.
    </>,
    <>
      Wrap everything that needs the draft in the provider. A send button
      outside the frame works as long as it is inside the provider.
    </>,
    <>
      Omit <code>ChatComposerCommonActions</code> when a composer needs a
      different set, and list its actions explicitly.
    </>,
    <>
      Wrap the whole conversation panel in <code>ChatComposerDropZone</code>, so
      files can land anywhere on it.
    </>,
    <>
      Render <code>ChatComposerCommandMenu</code> to turn slash commands on.
      Without it, / is just a character and the command button types one.
    </>,
    "Put suggested replies in the header. They fill the draft and never send on their own.",
    "Below 240px, use the one-row layout or leave out Common actions. The frame's minimum width stops the footer overlapping; it does not make the composer fit.",
    <>
      Return a promise from <code>onSubmit</code> for async sends. The send
      button shows busy, and a rejection keeps the draft.
    </>,
  ]}
