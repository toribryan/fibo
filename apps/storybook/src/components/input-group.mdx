# Input group

An input with an icon, text or button beside it, drawn as one field.

<Canvas of={Stories.Default} />

## Features

- Addons at the start or end hold an icon, text, a Kbd or a Button.
  Pressing an addon focuses the input.
- The group draws the border, focus ring and invalid state, so they wrap
  the addons too.
- `variant="ghost"` drops the border for a search at the top of a menu.
- The input is Base UI's Input, so a Field around the group labels,
  describes and validates it. `render` swaps in another input, such as an
  Autocomplete's.

## Examples

### Small

`size="sm"` matches a small Button or Select, as in a toolbar. Inside a
FieldGroup it takes the group's size.

### Ghost, in a menu

No border or background: the popup is the field. Command menu and Filter
menu draw their searches this way.

## Usage

```tsx
import {
  InputGroup,
  InputGroupAddon,
  InputGroupInput,
} from "@/components/ui/input-group"

export function Search() {
  return (
    <InputGroup>
      <InputGroupAddon>
        <SearchIcon />
      </InputGroupAddon>
      <InputGroupInput type="search" aria-label="Search" />
    </InputGroup>
  )
}
```

Put the label outside the group, in a FieldLabel or `aria-label`. An icon
in an addon is decoration, not a name.

## Guidelines

<UsageGuidelines
  guidelines={[
    "One addon on each side at most. More reads as a toolbar, not a field.",
    "Use a leading icon only when it says what the field is for, such as search or a handle's @.",
    "Use the ghost variant only where the surface around it marks the field, such as a popup's header.",
  ]}
/>
