# Tabs

Switches between views of one subject in place, such as sections of a
settings page. One tab is active; only its panel shows.

<Canvas of={Stories.Default} />

## Features

- Two list styles: a segmented control with a sliding pill under the active
  tab, or `variant="line"`, a bare row with an underline.
- `sm` (32px) and `default` (36px) sizes, matching Button and Input, plus
  vertical lists for a sidebar of sections.
- An overflowing row scrolls sideways instead of wrapping, keeping the active
  tab in view.
- Built on Base UI's Tabs: controlled or uncontrolled, arrow keys, Home and
  End, and panels linked to their tabs for screen readers.

## Examples

### Line

No track; the active tab takes the text color and a bar beneath. For the top
of a page or card, where a segmented control is too heavy.

<Canvas of={Stories.Line} />

### Small

`size="sm"` sets a 32px row, to sit beside small toolbar buttons.

<Canvas of={Stories.Small} />

### Vertical

`orientation="vertical"` on `Tabs` puts the list beside the panels. The line
variant's bar moves to the start edge; up and down arrows move between tabs.

<Canvas of={Stories.Vertical} />

### With icons and counts

Icons and Counts go in a trigger as children. Hide the icon with
`aria-hidden`; give the Count a `label` so it reads as more than a bare
number.

<Canvas of={Stories.WithIconsAndCounts} />

### Disabled tab

`disabled` on a trigger dims it. Arrow keys still reach it, so screen readers
announce it, but it can't be chosen. It stays in the row so the set doesn't
shift when it's re-enabled.

<Canvas of={Stories.DisabledTab} />

### Controlled

`value` and `onValueChange` drive the tabs from outside, here from a button
under the panel.

<Canvas of={Stories.Controlled} />

### Overflowing

Ten tabs in a narrow box. The row scrolls sideways with a hidden scrollbar,
starting at the active tab.

<Canvas of={Stories.Overflowing} />

## Usage

```tsx
import { Tabs, TabsContent, TabsList, TabsTrigger } from "@/components/ui/tabs"

export function Project() {
  return (
    <Tabs defaultValue="overview">
      <TabsList aria-label="Project">
        <TabsTrigger value="overview">Overview</TabsTrigger>
        <TabsTrigger value="activity">Activity</TabsTrigger>
      </TabsList>
      <TabsContent value="overview">Three releases this month.</TabsContent>
      <TabsContent value="activity">Ana merged the token change.</TabsContent>
    </Tabs>
  )
}
```

Each `TabsTrigger` needs a `TabsContent` with the same `value`. `variant` and
`size` go on `TabsList`, which passes them to its triggers.

## Guidelines

<UsageGuidelines
  guidelines={[
    "Use for views of one subject that people move between freely. Sequential steps need a stepper; site pages need links.",
    "Labels are one or two words, sentence case, nouns not actions.",
    "Segmented control for two to five short options near the content; line variant for sections of a page or card.",
    "Keep the set stable. Disable a tab that can't be used yet rather than removing it.",
    "Give every tab an icon or none; a partial set looks unfinished.",
  ]}
/>

<Tip>
  Panels unmount when hidden. <code>keepMounted</code> on{" "}
  <code>TabsContent</code> preserves a panel's state, such as a half-filled
  form, while another tab is open.
</Tip>

## API reference

`Tabs`, `TabsTrigger` and `TabsContent` take every prop of Base UI's
`Tabs.Root`, `Tabs.Tab` and `Tabs.Panel`. `TabsList` takes those of
`Tabs.List`, including `activateOnFocus` and `loopFocus`, plus `variant`
and `size`.
