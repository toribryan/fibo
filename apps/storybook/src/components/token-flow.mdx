# Token flow

Token flow shows a colour moving through the token tiers, from raw value to
primitive to semantic role.

<Canvas of={Stories.WithUse} />

Switch the theme in the toolbar: rows with a dark pair scramble to their dark
values while the semantic name stays put.

## Features

- One row per role: the raw value, the primitive and the semantic role, joined
  by wires.
- A pulse runs along each wire while the plate is on screen.
- Rows with a `dark` pair scramble to their dark values when the theme changes,
  while the role's name stays put.
- `showUse` prints what each role is for under its chip.

## Installation

<Install name="token-flow" exports={["TokenFlow", "type TokenRow"]} />

No animation library: the pulse and the scramble use the Web Animations API and
`requestAnimationFrame`.

## Usage

```tsx
import { TokenFlow } from "@/components/ui/token-flow"

export function PrimaryToken() {
  return (
    <TokenFlow
      rows={[
        {
          base: "oklch(0.205 0 0)",
          primitive: "neutral-900",
          semantic: "bg-primary",
          dark: { base: "oklch(0.985 0 0)", primitive: "neutral-50" },
        },
      ]}
    />
  )
}
```

Name the role the way people write it in code, and add a `dark` pair when the
role resolves differently in the dark theme.

## Guidelines

<UsageGuidelines
  guidelines={[
    "Use it in docs, case studies and onboarding, where the point is how a token is built, not what it looks like.",
    "Keep it to three to five rows, one per role.",
    <>
      Pick rows with a <code>dark</code> pair to show why semantic roles exist:
      the name stays put while the value underneath changes.
    </>,
    <>
      Turn on <code>showUse</code> when the reader doesn't know the role names
      yet.
    </>,
  ]}
/>

<Tip>
  By default the plate follows the document's <code>dark</code> class. A host
  that owns its own theme, such as a preview frame, can pin it with{" "}
  <code>theme</code>, and scope a <code>dark</code> class to a wrapper so the
  surfaces follow too.
</Tip>

## API reference

Each row takes a `base` value, a `primitive` name and a `semantic` role, plus
an optional `use` and a `dark` pair for roles that resolve differently in the
dark theme.
