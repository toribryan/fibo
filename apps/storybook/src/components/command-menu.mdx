# Command menu

A Cmd+K palette for navigation and actions, with nested pages, recents,
ranked search and a preview pane.

<Canvas of={Stories.Default} />

## Features

- **Nested pages.** An item with `items` opens a page instead of running,
  sliding in with a breadcrumb in the search row. Backspace on an empty
  search, the back button or Escape steps out.
- **Recents.** Run commands float to the top of the first page under Recent,
  labeled with their page. `storageKey` persists them across visits.
- **Ranked search.** Searching from the first page reaches every page.
  Ranking: whole-label match, label start, word start, anywhere in the label,
  then keywords, with recent commands nudged up. Matched letters are bold.
- **Preview pane.** Items with a `preview` open a pane beside the list that
  follows the highlight. Hidden below the `sm` breakpoint.

### Controlled

`trigger={null}` renders no trigger. `open` and `onOpenChange` control the
state, here from an external button or the shortcut.

### Non-modal

`modal={false}` doesn't trap focus, lock scroll or move focus into the menu,
and opening a page leaves focus in place. For a menu inside a card or cover
rather than over the page.

### Colored icons

An icon keeps a color set on it, e.g.
`icon: <GlobeIcon className="text-chart-2" />`. Icons without one stay muted.
Chart tokens are grays in fibo's theme and saturated in Mechanical.

## Usage

```tsx
import { useRouter } from "next/navigation"
import {
  CommandMenu,
  type CommandMenuGroup,
} from "@/components/ui/command-menu"

export function AppCommands({ setTheme }: { setTheme: (t: string) => void }) {
  const router = useRouter()
  const groups: CommandMenuGroup[] = [
    {
      label: "Go to",
      items: [
        {
          value: "inbox",
          label: "Inbox",
          onSelect: () => router.push("/inbox"),
        },
      ],
    },
    {
      label: "Actions",
      items: [
        {
          value: "theme",
          label: "Change theme",
          items: [
            {
              value: "light",
              label: "Light",
              onSelect: () => setTheme("light"),
            },
            { value: "dark", label: "Dark", onSelect: () => setTheme("dark") },
          ],
        },
      ],
    },
  ]
  return <CommandMenu groups={groups} storageKey="app-commands" />
}
```

Every `value` must be unique across the menu, nested pages included;
recents and ranking key on it. On select, the item's `onSelect` runs, then
the menu's `onSelect` receives the item, then the menu closes.

```ts
type CommandMenuItem = {
  value: string
  label: string
  icon?: React.ReactNode
  shortcut?: string[]
  keywords?: string[]
  disabled?: boolean
  onSelect?: () => void
  items?: CommandMenuItem[] // makes the item a page
  placeholder?: string // the search hint on that page
  preview?: React.ReactNode // shown in the side pane
}
```

Render one command menu per page. The shortcut listens on the document, so
two menus with the same `hotkey` both open.

## Guidelines

<UsageGuidelines
  guidelines={[
    "Use for navigation and for actions otherwise buried in menus.",
    "Start action labels with a verb (New file, Change theme); use plain names for places and things (Inbox, Roadmap 2027).",
    "Make an item a page when it needs a choice first: a theme, a person, a status. Keep pages one or two levels deep.",
    "Add keywords for synonyms: appearance for Change theme, create for New file.",
    "Add previews to items chosen by content, such as files and people. Omit them on plain actions.",
    "Don't make it the only path to anything. It is an accelerator.",
  ]}
/>

<Tip>
  An item's `shortcut` is only a label. Bind the keys in your app, or omit
  `shortcut`.
</Tip>
