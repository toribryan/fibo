# Command menu

A Cmd+K palette for moving around an app and running actions. Items can open
pages of their own, the commands you ran last come first, a search ranks
every command across every page, and a side pane previews the highlighted
one.

<Canvas of={Stories.Default} />

## Features

- **Nested pages.** An item with `items` opens a page instead of running,
  sliding in with a breadcrumb in the search row. Backspace on an empty
  search, the back button or Escape steps out.
- **Recents.** Commands you run float to the top of the first page under
  Recent, labelled with the page they live on. `storageKey` keeps them across
  visits.
- **Ranked search.** From the first page, a search reaches into every page.
  Whole-label matches rank first, then label starts, word starts, anywhere in
  the label, then keywords, with recent commands nudged up. The matched
  letters are bold.
- **Preview pane.** Items with a `preview` open a pane beside the list that
  follows the highlight. Below the `sm` breakpoint the pane hides.

## Examples

### Default

Change theme and Assign to open pages. Run something and reopen the menu to
see it under Recent. Type to search across every page at once.

### With preview

Files and people carry a `preview`, so the dialog widens and a pane follows

<Canvas of={Stories.WithRecents} />

### No matches

A search with no results says so, using `emptyText`.

<Canvas of={Stories.NoMatches} />

### Custom trigger

`trigger` swaps the search button for your own element.

<Canvas of={Stories.CustomTrigger} />

### Controlled

`trigger={null}` renders no trigger, and `open` with `onOpenChange` puts the
state in your hands, here opened by a button elsewhere on the page or the
shortcut.

<Canvas of={Stories.Controlled} />

### Non-modal

`modal={false}` opens the menu without trapping focus, locking the page's
scroll or moving focus into it, and opening a page leaves focus where it is.
Use it for a menu shown inside a card or a cover rather than over the page.

## Usage

```tsx
import { useRouter } from "next/navigation"
import {
  CommandMenu,
  type CommandMenuGroup,
} from "@/components/ui/command-menu"

export function AppCommands({ setTheme }: { setTheme: (t: string) => void }) {
  const router = useRouter()
  const groups: CommandMenuGroup[] = [
    {
      label: "Go to",
      items: [
        {
          value: "inbox",
          label: "Inbox",
          onSelect: () => router.push("/inbox"),
        },
      ],
    },
    {
      label: "Actions",
      items: [
        {
          value: "theme",
          label: "Change theme",
          items: [
            {
              value: "light",
              label: "Light",
              onSelect: () => setTheme("light"),
            },
            { value: "dark", label: "Dark", onSelect: () => setTheme("dark") },
          ],
        },
      ],
    },
  ]
  return <CommandMenu groups={groups} storageKey="app-commands" />
}
```

Every `value` must be unique across the whole menu, nested pages included:
recents and ranking find commands by it. An item runs its own `onSelect`,
then the menu's `onSelect` gets the item, and the menu closes.

```ts
type CommandMenuItem = {
  value: string
  label: string
  icon?: React.ReactNode
  shortcut?: string[]
  keywords?: string[]
  disabled?: boolean
  onSelect?: () => void
  items?: CommandMenuItem[] // makes the item a page
  placeholder?: string // the search hint on that page
  preview?: React.ReactNode // shown in the side pane
}
```

Render one command menu per page. Its shortcut listens on the whole
document, so two menus with the same `hotkey` would both open.

## Guidelines

<UsageGuidelines
  guidelines={[
    "Use it for moving around an app and running actions people would otherwise hunt for in menus.",
    "Start labels with a verb for actions (New file, Change theme) and use the plain name for places and things (Inbox, Roadmap 2027).",
    "Make an item a page when it needs a choice before it can run: a theme, a person, a status. Keep pages one or two levels deep.",
    "Add keywords for the words people might type instead: appearance for Change theme, create for New file.",
    "Give previews to things people pick between by content, such as files and people. Leave them off plain actions.",
    "Don't make it the only way to reach something. It speeds up people who know it's there.",
  ]}
/>

<Tip>
  A shortcut on an item is only a label. Wire the same keys up in your app, or
  leave `shortcut` off.
</Tip>
