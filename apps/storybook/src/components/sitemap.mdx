# Sitemap

A site directory page: a search, then every destination in a few groups.

<BlockPreview label="Sitemap">
  {() => <Sitemap onSearch={() => {}} />}
</BlockPreview>

## Features

- A search at the top with popular picks under it, optionally pinned below
  the site's header on scroll.
- Four columns wide, two on a tablet, one card per group on a phone. The
  layout follows the block's own width, not the viewport.
- Groups nest one level deep, such as a state and its cities, and can fold
  behind a toggle.
- Every link takes `render`, so a router's `Link` keeps the styling.

## Installation

<Install name="sitemap" block exports={["Sitemap"]} />

Also installs Button and Input group. Render it with `onSearch` or a
`searchAction` route:

```tsx
import { Sitemap } from "@/components/blocks/sitemap/sitemap"

export default function Page() {
  return <Sitemap searchAction="/search" />
}
```

Once installed, the block's files belong to your app. Running `shadcn add`
again overwrites your edits.

## Files

| File          | Holds                                                          |
| ------------- | -------------------------------------------------------------- |
| `sitemap.tsx` | The page, built from `data.ts`.                                |
| `parts.tsx`   | The parts: layout, header, search, suggestions and directory.  |
| `data.ts`     | The title, search hint, suggestions and every section's links. |

## Make it yours

1. Replace `data.ts` with your site's pages. An entry with `links` becomes
   a group, such as a state and its cities.
2. Point the search at your results route with `searchAction`, or handle it
   with `onSearch`.
3. Pass a router's `Link` to `SitemapLink` and `SitemapSuggestion` through
   `render` in `sitemap.tsx`, so links route without a page load.

## Usage

For a different page shape, compose the parts from `parts.tsx`.
`SitemapLayout` is the frame whose width the rest lays out by.

```tsx
import {
  SitemapGroup,
  SitemapHeader,
  SitemapLayout,
  SitemapLink,
  SitemapSearch,
  SitemapSection,
  SitemapSections,
  SitemapTitle,
} from "@/components/blocks/sitemap/parts"

type Location = {
  state: string
  href: string
  cities: { name: string; href: string }[]
}

export function SitemapPage({ locations }: { locations: Location[] }) {
  return (
    <SitemapLayout>
      <SitemapHeader>
        <SitemapTitle>Explore care homes</SitemapTitle>
      </SitemapHeader>
      <SitemapSearch action="/search" />
      <SitemapSections>
        <SitemapSection title="Browse locations">
          {locations.map((location) => (
            <SitemapGroup
              key={location.state}
              title={location.state}
              href={location.href}
              collapsible
            >
              {location.cities.map((city) => (
                <SitemapLink key={city.name} href={city.href}>
                  {city.name}
                </SitemapLink>
              ))}
            </SitemapGroup>
          ))}
        </SitemapSection>
      </SitemapSections>
    </SitemapLayout>
  )
}
```

Build location links from the pages the site has, not a hand-kept list.

## Guidelines

<UsageGuidelines
  guidelines={[
    "Keep it to three to five groups, named by what people came to do: find, browse, learn, contact.",
    "Put the search first when most visitors arrive looking for a place. The directory backs it up, not replaces it.",
    "Fold long location lists with collapsible groups, and leave the first group open.",
    "List only destinations that exist. Drop a link rather than point it at an empty page.",
    "This page is for people. Keep the XML sitemap for search engines separate.",
  ]}
/>

<Tip>
  Pin the search only under a short site header. Two stacked sticky bars on a
  phone leave little room for the page.
</Tip>
