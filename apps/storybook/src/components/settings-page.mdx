# Settings page

A settings screen in three tabs, Profile, Notifications and Account, with a
save bar that appears on any edit and Cmd+S or Ctrl+S from any field.

<BlockPreview label="Settings page">
  {(container) => <SettingsPage container={container} className="min-h-full" />}
</BlockPreview>

## Features

- **One form, one save.** All tabs edit the same settings and save together.
  The save bar shows while anything differs from the last save; Discard
  reverts it all.
- **Validated on save.** An empty name stops the save, switches to Profile
  and marks the field.
- **Confirmed danger zone.** Delete account opens an Alert dialog with
  Cancel focused.
- **Lays out by its own width.** Wide, each group's heading sits beside its
  fields; narrow, it stacks above them.

## Installation

<Install name="settings-page" block exports={["SettingsPage"]} />

Render it and persist in `onSave`:

```tsx
import { SettingsPage } from "@/components/blocks/settings-page/settings-page"

export default function Page() {
  return (
    <SettingsPage
      initialValues={settings}
      onSave={(next) => saveSettings(next)}
    />
  )
}
```

Once installed, the block's files belong to your app. Running `shadcn add`
again overwrites your edits.

## Files

| File                | Holds                                                           |
| ------------------- | --------------------------------------------------------------- |
| `settings-page.tsx` | The form, the tabs, the save bar, the shortcut and the Toaster. |
| `sections.tsx`      | Profile, Notifications and Account, with the danger zone.       |
| `data.ts`           | The settings type, the starting values and the option lists.    |

## Make it yours

1. Change the `Settings` type in `data.ts` to what your app stores, then add
   or remove fields in `sections.tsx`.
2. Pass loaded values as `initialValues` and persist in `onSave`. Values are
   marked saved only once `onSave` returns, so a throw keeps the save bar
   up. For a network save, make `save` in `settings-page.tsx` async and
   await it.
3. If your app already mounts a Toaster, remove the one at the bottom of
   `settings-page.tsx`.
4. Wire Delete account to your own flow in `sections.tsx`. As shipped it
   shows a toast and deletes nothing.
