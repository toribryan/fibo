## When to use it

Use Field around every form control: it names the control from `FieldLabel`
and describes it with `FieldDescription` without `id`s, for Input, Textarea,
Select, Checkbox, Radio group, Switch and Slider. One control per Field. For a
group of options, put the Radio group in the Field and each option in a
`FieldItem`. `FieldGroup size="sm"` makes every control inside it small.

## Invalid

Set `invalid` from client validation or a server response. The control's
border turns destructive and `FieldError` shows.

<Preview>
  <Field invalid className="w-80">
    <FieldLabel>Work email</FieldLabel>
    <Input type="email" placeholder="you@company.com" />
    <FieldDescription>We send receipts here.</FieldDescription>
    <FieldError>Enter an email address.</FieldError>
  </Field>
</Preview>

## Horizontal

`orientation="horizontal"` places a checkbox or switch beside its label. A
checkbox leads its label; a switch follows it. `FieldContent` stacks the label
and description.

<Preview>
  <div className="flex w-80 flex-col gap-6">
    <Field orientation="horizontal">
      <Checkbox className="mt-0.5" />
      <FieldContent>
        <FieldLabel>Email me about replies</FieldLabel>
        <FieldDescription>At most once an hour.</FieldDescription>
      </FieldContent>
    </Field>
    <Field orientation="horizontal">
      <FieldContent>
        <FieldLabel>Read receipts</FieldLabel>
        <FieldDescription>Show when you've read a message.</FieldDescription>
      </FieldContent>
      <Switch defaultChecked />
    </Field>
  </div>
</Preview>

## Accessibility

- FieldLabel is a label element tied to the control; clicking it focuses or
  toggles the control.
- FieldDescription and FieldError are linked with `aria-describedby` and read
  with the control.
- `invalid` also sets `aria-invalid` on the control, so state isn't conveyed
  by color alone.
