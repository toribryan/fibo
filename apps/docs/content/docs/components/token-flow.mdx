## When to use it

Use Token flow to show how a color token is built: one row per role, its raw
value, primitive and semantic role joined by wires, with a pulse along each
wire while the plate is on screen. Rows with a `dark` pair scramble to their
dark values when the theme changes while the role's name stays put. Try the
site's theme switch. `showUse` prints what each role is for under its chip.

## Installation

<Install name="token-flow" exports={["TokenFlow", "type TokenRow"]} />

No animation library; the pulse and scramble use the Web Animations API and
`requestAnimationFrame`.

## Vertical

`orientation="vertical"` stacks the tiers at every width, for a narrow column
or card. The default stacks only on narrow screens.

## Guidelines

<UsageGuidelines
  guidelines={[
    "Use in docs, case studies and onboarding, where the point is how a token is built, not how it looks.",
    "Three to five rows, one per role.",
    <>
      Rows with a <code>dark</code> pair show why semantic roles exist: the name
      stays put while the value changes.
    </>,
    <>
      Turn on <code>showUse</code> when readers don't know the role names yet.
    </>,
  ]}
/>

<Tip>
  The plate follows the document's `dark` class. A host with its own theme, such
  as a preview frame, can pin it with `theme` and scope a `dark` class to a
  wrapper so the surfaces follow.
</Tip>

## Accessibility

- Each chip carries its tier in screen-reader text, so it reads as
  "Primitive neutral-900", not a bare value.
- Scrambled text is hidden from assistive tech; only the settled value is
  announced.
- The pulse runs only while the plate is on screen. Neither pulse nor
  scramble plays under prefers-reduced-motion.
