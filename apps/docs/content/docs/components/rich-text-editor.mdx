## When to use it

Use Rich text editor where formatting changes meaning: notes, proposals,
release notes, replies. Formatting comes from the toolbar, a shortcut, or
Markdown as you type (`## `, `- `, `1. `, `> `, backticks). For a plain
message or short answer, use Textarea or Chat composer.

The writing area isn't a form control, so a label's `for` can't target it.
Name it with `aria-labelledby` and the label's `id`. The editor owns the
document once mounted: `defaultValue` seeds it and `onChange` reports changes
as HTML. Sanitize that HTML on the server before showing it to anyone else.

## Minimal tools

`tools` picks which buttons show. They keep the toolbar's order regardless of
list order.

<Preview>
  <div className="w-full max-w-xl">
    <RichTextEditor
      label="Comment"
      tools={["bold", "italic", "link"]}
      minHeight={80}
      placeholder="Add a comment…"
    />
  </div>
</Preview>

## With a limit

From 80% of `maxLength`, the remaining count shows in the corner and turns
destructive at the limit.

<Preview>
  <div className="w-full max-w-xl">
    <RichTextEditor
      label="Release note"
      maxLength={120}
      minHeight={140}
      defaultValue="<p>Keep release notes short: what changed, who it affects, and what to do next. Link the pull request, not the diff.</p>"
    />
  </div>
</Preview>

## Read only

`editable={false}` drops the toolbar and shows the document as it reads.

## Accessibility

- The writing area is a multi-line `textbox`, named by `aria-labelledby` when
  it's given and by `label` otherwise. Point `aria-labelledby` at a visible
  label.
- The toolbar is one tab stop. Arrow keys, Home and End move between its
  buttons, following the ARIA toolbar pattern. Marks and blocks carry
  `aria-pressed`.
- Clicking a tool keeps focus and the selection in the writing area. Running
  one from the keyboard sends focus back there.
- Undo and Redo stay focusable when disabled, so the toolbar's keyboard path
  never changes length.
- Escape closes the link row and returns to the writing area. The visible
  count is hidden from screen readers; a separate `aria-live="polite"` region
  reads it when it first shows, at each further ten characters, and at the
  limit, not on every keystroke.
