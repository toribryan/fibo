## When to use it

Use Alert dialog for a modal question before a step that can't be undone,
such as deleting a project. It's announced as a question that needs an
answer, and Cancel takes focus on open, so Enter alone never confirms. There
is no close button and no click-outside dismiss: only Cancel or Escape
leaves. It shares Dialog's look and motion, `sm` by default.

## Installation

<Install
  name="alert-dialog"
  exports={[
    "AlertDialog",
    "AlertDialogTrigger",
    "AlertDialogContent",
    "AlertDialogHeader",
    "AlertDialogTitle",
    "AlertDialogDescription",
    "AlertDialogFooter",
    "AlertDialogCancel",
    "AlertDialogAction",
  ]}
/>

It installs Dialog, for the shared styles, and Button with it.

Cancel goes before the action in the footer, since it takes focus. Both
close the dialog. For an action that has to finish first, control `open` and
close it when the work is done.

## Not destructive

A confirmation that loses nothing, such as publishing, keeps the default
button.

## Guidelines

<UsageGuidelines
  guidelines={[
    "Ask only when the step can't be undone, or undoing it is costly. Otherwise do it and offer Undo in a Toast.",
    "Ask a question in the title that names the thing: Delete Atlas redesign?, not Are you sure?",
    "Say what's lost in the description, in one or two sentences.",
    "Label the action with the verb from the title, and use the destructive variant when something is deleted.",
  ]}

## Accessibility

- Named by AlertDialogTitle and described by AlertDialogDescription, so the
  question is read out on open.
- Focus is trapped inside and returns to the trigger on close.
- Escape cancels. A click outside does nothing, so a stray click can't
  dismiss the question.
