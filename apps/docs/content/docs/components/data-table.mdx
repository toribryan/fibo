## When to use it

Use Data table for lists people work through: selecting rows, sorting,
searching, filtering and acting on them in bulk. `useDataTable` takes rows and
columns, and TanStack Table computes the rows and holds the state, so sorting,
search, filters with counts, pages, selection and column visibility need no
further code. Data table renders a native table matching the Figma library.
For a plain read-only grid, use Table.

## Empty and no matches

With no rows, the body says so. When a search or filter hid them, it says
nothing matched and offers Clear filters, which returns focus to the search.
`empty` replaces the copy; `empty={null}` leaves the body blank.

## Accessibility

- It's a native table, not a grid: checkboxes and buttons are ordinary Tab
  stops. TanStack Table only works out the rows; the markup is Data table's.
- Every head carries `scope="col"`. A sortable head holds a button named by
  the column. Only the sorted head carries `aria-sort`, ascending or
  descending, so the order is announced once, where it applies.
- DataTableSearch is a search field; give it an `aria-label` when there's no
  visible label. Facet filter menus name each choice with its count,
  “Active 3”, and say how many are ticked on the button.
- Name it with `aria-label` or `aria-labelledby` on DataTable.
- Each row checkbox is named from its primary or person cell, “Select Maya
  Okafor”. Select all says its scope, “Select all members on this page”.
- A locked row's checkbox is disabled and described by the reason. The lock
  is focusable, so keyboard users can open its tooltip.
- Selection changes are announced through a status region once they take
  effect, so a change a controlled parent turns down isn't announced. Escape
  clears the selection.
- The toolbar is a group named “Filters and actions” or “Bulk actions”, not a
  toolbar role, so its controls stay ordinary Tab stops and arrow keys stay
  with the search field.
- When the focused control goes away, such as Clear or Select all matching,
  focus moves to Clear, or to select all when nothing is selected, instead of
  the page.
- A single-row action that's dimmed stays focusable and is described by why:
  “Works on one member at a time”.
- Only one of the table and the cards is ever in the page, so screen readers
  don't meet each row twice. Cards are a list, and each card's checkbox is
  named from its title.
- Icon-only actions on a narrow table keep their label as their accessible
  name and show it as a tooltip.
- Status badges sit on the background, so their tints keep AA contrast on
  selected and hovered rows.
