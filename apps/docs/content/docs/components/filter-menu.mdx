## When to use it

Use Filter menu above a list or table filtered by several fields. Pick a
field such as Status, then check any number of its values; each field shows a
count of what's selected. The menu only picks filters, so the app shows the
applied ones, here as removable chips. `value` holds chosen values keyed by
field id, such as `{ status: ["todo"] }`.

## Installation

<Install
  name="filter-menu"
  exports={["FilterMenu", "type FilterField", "type FilterValue"]}
/>

It installs Button and `motion` with it.

## Search

Uncontrolled. The Search filters button, or typing a letter, slides the menu
to a search grouped by field, with matched letters in bold. It lists every
value until you type. Back, Escape or Backspace returns.

## Inline search

`search="inline"` puts a search box at the top instead. Typing turns the menu
into results in place, and clearing the text restores it.

## Accessibility

- On open, the list takes focus and points at the highlighted row with
  aria-activedescendant, so screen readers announce each row as the arrows
  move. The Search filters button is one Tab away.
- Entering search moves focus to the search box, a combobox using
  aria-activedescendant the same way. Leaving search returns focus to the
  list.
- With inline search, focus goes to the search box on open and stays there.
- Values are options in a multi-select listbox, announced as selected or not.
  Each field announces its selected count and that it opens its values.
- Searches announce the result count.
- Escape steps back one level at a time; the last press returns focus to the
  Filter button.
- Localize all text: the trigger with `triggerLabel`, the popup with `label`,
  and the search box with `searchLabel` and `placeholder`.
